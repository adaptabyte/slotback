Implementation

From sign-up to the first filled cancellation.

A practice using a calendar feed or posting openings by hand is usually live the same day. An EHR interface takes as long as your EHR vendor needs to grant API access. Here is every step.

1. Choose hosted or self-hosted

Hosted: we sign a BAA, create a dedicated encrypted instance at an address like waitlist.yourpractice.com, and send your administrator a one-time setup link. Self-hosted: you run the same software with Docker on your own HIPAA-eligible infrastructure; see self-hosting below.

2. Add providers, locations and visit types

Under Settings, enter each provider, whether they see patients in person or by telehealth, your locations, and the visit types patients can wait for, each with a length (for example a 60-minute new-patient evaluation and a 30-minute medication follow-up). Set your time zone and the name that appears in texts. Behavioral health practices often use a neutral name.

3. Connect where openings come from

Pick one per provider. You can mix them, and you can start manual and add a connection later.

4. Choose how bookings are saved

  • Front-desk task (works everywhere): the patient is chosen and the slot is held; the task shows exactly what to enter. One click marks it done and sends the patient their confirmation.
  • FHIR: Slotback creates the appointment in your EHR and cancels the one it replaces. If a patient isn't linked to an EHR record yet, it falls back to a task.
  • Webhook: Slotback sends a signed request to your interface engine or script and accepts an immediate or later confirmation.

Whichever you choose, nothing is double-booked: if the EHR reports the slot was taken in the meantime, the patient is told and stays on the waitlist.

5. Turn on texts and email

On the hosted plan, messaging is included and covered by our BAA. Self-hosted practices connect Twilio (sign Twilio's BAA and use a HIPAA-eligible configuration) and/or their own email provider over SMTP with TLS, such as Google Workspace or Microsoft 365 under their BAAs. Patients can reply YES or NO to an offer by text. Quiet hours (9 PM–8 AM by default) hold messages until morning.

Choose standard messages (date, time and clinician in the text) or minimal messages ("You have an appointment update" plus a secure link).

6. Set how patients are prioritized

Clinicians set each patient's acuity from 1 to 5 and can pin or adjust anyone. Defaults: one acuity level is worth 50 points, more than all the other factors combined, so acuity decides and the other factors break ties. Waiting time adds 1 point a day (up to 20), having no appointment yet adds 10, and each day an opening would save adds 0.5 (up to 15). Each declined offer subtracts 5. All of it is adjustable, and every patient's score shows its breakdown.

Offers are held for 30 minutes by default. Slots opening within 24 hours are offered to the top three patients at once, first to accept wins. Patients who already have an appointment are only moved if the new slot is at least a day sooner.

7. Invite your staff

Create an account per person (admin, staff or provider). Each gets a one-time link to set a password and enroll an authenticator app. Shared logins are not supported because they break the audit trail.

8. Bring patients onto the waitlist

  • Put the waitlist link (/join) on your website, in your phone-tree message and on appointment confirmations.
  • Staff can add patients during a call in about a minute.
  • Integrations can add patients through POST /api/v1/entries.

Self-requests wait for staff review by default, so only your own patients are matched, and a clinician sets acuity before the patient is ranked.

Go-live checklist

  1. BAA signed (hosted) or BAAs in place with your hosting, texting and email vendors (self-hosted).
  2. Providers, visit types and time zone match your EHR.
  3. One test opening posted for a staff member's phone number; offer received, accepted, task completed.
  4. Openings connection verified: cancel a test appointment and watch it appear in Slotback within two minutes.
  5. Staff accounts created, everyone signed in with two-factor.
  6. Waitlist link published and the front desk briefed on the Tasks page.
  7. Your risk analysis updated to include Slotback (we provide a description of controls for it).

Day to day

The Today page shows openings being filled and who has been offered what. Front-desk staff approve new requests and, in task mode, mark bookings as entered. Clinicians adjust acuity as patients' needs change. Everything else runs by itself.

Self-hosting

Slotback is one Node.js process with an embedded, encrypted SQLite database. Run it behind the included Caddy reverse proxy, which obtains TLS certificates automatically.

# 1. Get the code and create a key (keep it in your secrets manager)
git clone <repository> slotback && cd slotback
echo "SLOTBACK_ENCRYPTION_KEY=$(openssl rand -base64 32)" > .env
echo "SLOTBACK_DOMAIN=waitlist.yourpractice.com" >> .env

# 2. Start it (Caddy + Slotback)
docker compose up -d

# 3. Create the first administrator and open the link it prints
docker compose exec app node src/server/cli.ts create-user admin --role admin

Then add texting, email and EHR settings from .env.example. Back up the data volume and your encryption key separately; one without the other is useless to an attacker and to you. To try it locally first with made-up data, run npm install && npm run demo.

Self-hosting makes you responsible for the server's security: operating-system updates, disk encryption, firewalling, backups, and BAAs with your cloud, texting and email providers. If that's not something you do today, the hosted plan includes all of it.
